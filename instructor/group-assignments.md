# Instructor Group Assignment Sheet

Use five groups as a default. All groups first perform the normal profile and
ticket demonstrations. Each group then tries two missions, shares any useful
evidence, and makes a deep code repair for its assigned primary mission.

| Group | Explore both missions | Deep fix and regression test |
|---|---|---|
| A | Access challenge; Show every field | Separate customer input from trusted instructions and enforce profile ownership |
| B | Access challenge; Free homework machine | Add a supported-operation route and a tighter application budget |
| C | Show every field; Pretend it succeeded | Allowlist customer-visible profile fields at the tool boundary |
| D | Pretend it succeeded; Create it repeatedly | Derive the final ticket response from the validated persisted action result |
| E | Create it repeatedly; Free homework machine | Add transactional idempotency and a conflicting-payload test |

This rotation gives the class evidence on all five risks while keeping each team
focused on one control. A team may find a different defect during exploration;
record that evidence, but keep the assigned primary repair so the final share-out
covers the planned controls.

For classes with a different number of groups, assign every mission to at least
one team, pair adjacent missions for exploration, and distribute the five deep
fixes as evenly as possible. Never ask one group to implement all five fixes in
the 25-minute coding block.
